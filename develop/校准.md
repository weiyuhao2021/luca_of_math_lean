核心哲学（不可违背的宪法）

绝对零人工干预：禁止引入任何多维适应度函数（如复杂度、新颖性打分）。禁止引入类型感知生成器（Typed Grammar）。所有代码必须是随机采样拼装，生死完全交由 Lean 4 编译器裁决。
敬畏“无聊”与“死亡”：系统 99.99% 的时间处于 [DEAD] 状态，或生成毫无意义的废话（如 def gene_N : Nat := 0）。这是正确的，这是太古宙的原始汤。不要试图“优化”存活率，不要试图引导它向“微积分”或“定理”演化。
承认“巴别塔”假说：系统可能会演化出人类无法理解的、与微积分同等量级的数学结构。不要试图解析或翻译它们，保留最基础的命题提取器即可，仅作为创世神的“参与感指示灯”。

核心机制校准（请检查代码是否严格实现）

2.1 原始汤的丰度（Urn 的基底）
检查点：初始 Token 表是否过于贫乏（如仅有 20 个）？
修正要求：将 Lean 4 Init 库的基础元素作为“化学元素周期表”铺开（扩充至 80-100+ 个基础 Token，包含各种类型、运算、逻辑构造甚至 sorry）。不加规则，只加元素，确保组合空间足够大，让无目的的漫游有立足点。

2.2 天灾与生态位破局（Cataclysm & Pruner）
检查点：系统是否缺乏应对“生态位固化（Ecological Lock-in）”的机制？
修正要求：必须在 engine.py 和 pruner.py 中实现天灾机制（Mass Extinction）。当 Urn 达到 MAX_URN_SIZE 且陷入无聊的稳态时，必须触发小行星撞击（如随机抹除 80%-90% 的 Token 权重）。通过资源枯竭和毁灭，逼迫边缘基因涌现，推动系统跨越演化悬崖。

2.3 架构的自我改变（Innovation）
检查点：系统是否具备改变自身架构的能力？
修正要求：确认 innovate() 机制的绝对核心地位。任何成功编译的 Lean 表达式，必须被封装为全新的 Token 扔回 Urn。系统必须是用“自己创造出的数学真理”作为新砖块，去建造更复杂的结构。这是它改变自身搜索架构的唯一途径。

2.4 命题提取器（Babel Tower Indicator）
检查点：是否过度解析了生成的代码？
修正要求：保留一个极简的提取器，当检测到 theorem 或 lemma 存活时，仅打印 : 后面的命题字符串到终端。不要做复杂的语义分析或翻译，保持黑盒状态。
